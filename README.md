# Grupo 3 — Busca Vetorial Simples com Oracle

Busca semântica no FAQ de suporte de um sistema fictício (**Órbita ERP**), usando o Oracle como banco vetorial.

```
Texto → Embedding local (Python) → VECTOR no Oracle → VECTOR_DISTANCE (cosseno) → Top 5
```

A ideia: o usuário descreve o problema com as próprias palavras ("errei a senha várias vezes e não entra mais") e o sistema encontra a resposta certa ("Usuário bloqueado após tentativas de login"), mesmo sem palavras em comum.

## Como rodar

Pré-requisitos: [Docker Desktop](https://www.docker.com/products/docker-desktop/) (Mac, Windows ou Linux), ~8 GB livres em disco e pelo menos 4 GB de memória liberados para o Docker.

```bash
git clone https://github.com/BrayanRezende/oracle-dba-adm-grupo-3.git
cd oracle-dba-adm-grupo-3
docker compose up -d --build
```

- O primeiro build pode levar de 10 a 30 minutos, dependendo da internet: baixa o Oracle (~2,5 GB), o PyTorch e o modelo de embedding. Os próximos são rápidos.
- Quando subir, a aplicação carrega o FAQ automaticamente no Oracle.
- Acompanhe com `docker compose logs -f app` até aparecer `Application startup complete`.

Depois abra:

| Endereço | O quê |
|---|---|
| http://localhost:8000 | Tela de busca (aceita `?q=pergunta` para abrir já buscando) |
| http://localhost:8000/docs | Documentação da API (Swagger) |
| `localhost:1521/FREEPDB1` | Oracle (usuário `grupo3`, senha `grupo3`) |

Para parar: `docker compose down`. Para apagar também os dados do banco: `docker compose down -v`.

> Porta 1521 ou 8000 já ocupada? Copie `.env.example` para `.env` e troque `ORACLE_PORT` / `APP_PORT`.

## Arquitetura

```

│ Navegador  │ ──────────────▶ │ app (Python / FastAPI)       │ ─────▶ │ oracle (26ai Free)        │
```

Os dois containers sobem com `docker compose`:

- **oracle**: imagem oficial `container-registry.oracle.com/database/free:latest-lite`. Toda vez que sobe, roda [`docker/oracle/startup/01-init.sh`](docker/oracle/startup/01-init.sh), que cria (se ainda não existirem):
  - o tablespace `GRUPO3_DATA`;
  - o usuário `grupo3` no PDB `FREEPDB1`;
  - a tabela de [`sql/01-create-table.sql`](sql/01-create-table.sql).
- **app**: Python 3.12 com FastAPI. O modelo de embedding já vem baixado dentro da imagem, então a demo funciona sem internet.

## Conceitos

### O que é embedding
É um vetor de números que representa o **significado** de um texto. Um modelo de linguagem lê o texto e devolve, neste projeto, **384 números**. Textos com sentidos parecidos geram vetores que apontam para direções parecidas.

```python
from sentence_transformers import SentenceTransformer
model = SentenceTransformer("intfloat/multilingual-e5-small")
vetor = model.encode("query: esqueci minha senha", normalize_embeddings=True)  # 384 floats
```

### Modelo escolhido
[`intfloat/multilingual-e5-small`](https://huggingface.co/intfloat/multilingual-e5-small):

- é **multilíngue** e entende português (o `all-MiniLM-L6-v2` do exemplo do enunciado foi treinado basicamente em inglês);
- foi **treinado para busca**, ou seja, para comparar uma pergunta curta com um documento longo;
- é leve: roda em CPU, sem GPU;
- gera **384 dimensões**.

O E5 pede um prefixo que indica o papel do texto:

- `"query: "` na pergunta do usuário;
- `"passage: "` no documento da base.

Antes de escolher, comparamos com o `paraphrase-multilingual-MiniLM-L12-v2` (também 384 dims) em 16 perguntas de teste:

| Modelo | Resposta certa em 1º | Resposta certa no top 3 |
|---|---|---|
| paraphrase-multilingual-MiniLM-L12-v2 | 8 / 16 | 13 / 16 |
| **multilingual-e5-small** | **12 / 16** | **15 / 16** |

> Observação: no E5 as distâncias ficam numa faixa estreita (~0,10 a 0,20). O que importa é a **ordem**, não o valor absoluto.

### Coerência modelo ↔ vetor ↔ consulta
As três partes usam o mesmo número, 384:

| Onde | Valor |
|---|---|
| Modelo (`embeddings.py`) | gera 384 dimensões (validado ao carregar) |
| Coluna (`01-create-table.sql`) | `VECTOR(384, FLOAT32)` |
| Insert e busca (`db.py`) | `TO_VECTOR(:v, 384, FLOAT32)` |

Se alguém trocar o modelo por um de outra dimensão, a aplicação recusa iniciar e o Oracle recusa o insert.

### Distância de cosseno
O `VECTOR_DISTANCE(a, b, COSINE)` mede o ângulo entre dois vetores:

- **0** = mesmo significado;
- **~1** = sem relação;
- quanto **menor**, mais parecido.

A busca ordena os documentos por essa distância e pega os 5 primeiros.

## Banco de dados

```sql
CREATE TABLE IF NOT EXISTS kb_docs (
  id         NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  titulo     VARCHAR2(200) NOT NULL,
  texto      CLOB NOT NULL,
  embedding  VECTOR(384, FLOAT32) NOT NULL,
  created_at TIMESTAMP DEFAULT SYSTIMESTAMP NOT NULL
);
```

- O embedding de cada documento é gerado a partir de `"passage: " + titulo + texto`.
- Trocou o modelo? Todos os vetores precisam ser gerados de novo (`python seed.py`). Vetores de modelos diferentes não podem ser comparados entre si.
- Na aplicação, o vetor vai do Python ao Oracle como binário (`array('f')` → tipo `VECTOR` nativo do driver `python-oracledb`). Isso é mais eficiente que mandar como texto.
- Nos scripts SQL, o mesmo vetor aparece em texto (`'[0.01, -0.03, ...]'`), para ficar fácil de visualizar.

| Arquivo | Conteúdo |
|---|---|
| [`sql/01-create-table.sql`](sql/01-create-table.sql) | criação da tabela |
| [`sql/02-inserts.sql`](sql/02-inserts.sql) | insert de 2 documentos novos com embeddings reais de 384 dimensões |
| [`sql/03-search.sql`](sql/03-search.sql) | busca com o embedding real de uma pergunta, documentos parecidos e inspeção do vetor |

Os arquivos 02 e 03 são gerados por [`app/exportar_sql.py`](app/exportar_sql.py). Para rodar um deles no SQL*Plus:

```bash
docker exec -i grupo3-oracle sqlplus -s grupo3/grupo3@//localhost:1521/FREEPDB1 < sql/03-search.sql
```

Para abrir o SQL*Plus dentro do container:

```bash
docker exec -it grupo3-oracle sqlplus grupo3/grupo3@//localhost:1521/FREEPDB1
```

## API

| Método | Rota | Corpo | Retorno |
|---|---|---|---|
| `POST` | `/search` | `{"pergunta": "...", "top_k": 5}` | resultados (título, texto, distância), o vetor da pergunta, o vetor do 1º resultado e o tempo de cada etapa |
| `POST` | `/documents` | `{"titulo": "...", "texto": "..."}` | cadastra um documento (gera o embedding e grava) |
| `GET` | `/documents` | — | lista os documentos |
| `GET` | `/stats` | — | quantidade de documentos, modelo e dimensões |

```bash
curl -s localhost:8000/search -H 'Content-Type: application/json' \
  -d '{"pergunta": "a SEFAZ recusou minha nota"}'
```
